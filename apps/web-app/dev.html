登录 token 流

token 类型access 业务面单 token
登录端点POST /u/a/noau/token
header 必带X-Captcha-Id: <captcha-id>
token 用法Authorization: Bearer <access_token>
完整 captcha 流: ① POST /api/v1/c/captcha/generate/ 拿 captcha-id → ② 用户输入文字 POST /api/v1/c/captcha/validate/(后端写 Redis user:capt:{id}) → ③ 调 /u/a/noau/token 时 header 必带 X-Captcha-Id。

登录 token 流(双 token)

业务 tokenaccess 同 CE 流程(captcha + X-Captcha-Id)
平台登录POST /api/v1/p/auth/login EE+
平台 tokenplatform_access claim 内含 token_type=platform_access
平台 API 用法Header Authorization: Bearer <platform_access>
中间件对 /api/v1/p/* 跳过业务 token 校验,鉴权完全交给 router 的 dependency。业务 access 调 /api/v1/p/* 会被拒(Wrong token type),反之亦然。

外部入口 EE+

OIDC 登录/api/v1/p/sso/oidc/login
OIDC 回调/api/v1/p/sso/oidc/callback
LDAP 登录/api/v1/p/sso/ldap/login
配置段sso.oidc / sso.ldap (yinghuo.yaml)
敏感字段YH_OIDC_CLIENT_SECRET / YH_LDAP_BIND_PASSWORD
SSO 登录成功后产 platform_access token,与平台 token 流汇合。
